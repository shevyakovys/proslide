# sfedu-slide

Сервис переименован из ProSlide в **sfedu-slide**. Адрес сайта, репозиторий, база и ключи сессий сохранены: существующие аккаунты, презентации, QR-ссылки и история продолжают работать.

### Обновлённый редактор

- Название задаётся при создании; затем редактируется в явном поле шапки или кнопкой «Переименовать» в библиотеке.
- Слайды можно перетаскивать, двигать кнопками «Выше/Ниже», отправлять на выбранную позицию и перемещать с клавиатуры Alt+↑/↓ на миниатюре.
- Размер и цвет заголовка и описания задаются отдельно. Оформление можно применить ко всем слайдам или сбросить к цветовой теме.
- Работают автосохранение, Ctrl+S, индикатор ошибок сохранения, отмена и повтор последних действий в текущем редакторе.
- Новый слайд добавляется сразу после выбранного. Изменения заголовков сразу отражаются в миниатюрах.
- Оформление передаётся в режим показа и на экран участника; размеры адаптируются к небольшим экранам.

Новые параметры `slides[].textStyle` необязательны. Старые записи не переписываются при обновлении сервиса, а запущенные сессии сохраняют собственные снимки презентаций. Смена оформления в редакторе применяется к следующему запуску показа.

Самостоятельный сервис интерактивных презентаций: автор создаёт слайды и проводит выступление, участники подключаются по QR-коду или шестизначному коду и отвечают с телефона. Русский адаптивный интерфейс. Реализован основной сценарий сервиса, вдохновлённый [Юнислайдом](https://unislide.ru/), с собственными кодом и оформлением.

## Онлайн-версия

**[Открыть ProSlide](https://shevyakovys.github.io/proslide/)**

Интерфейс публикуется на **GitHub Pages**, API работает в **Supabase Edge Functions**, данные хранятся в **Supabase PostgreSQL**. Компьютер автора не должен постоянно работать как сервер. Откройте сайт, создайте аккаунт автора, подготовьте презентацию и нажмите «Начать показ». Участники входят с телефонов по QR-коду или ссылке `https://shevyakovys.github.io/proslide/#/join/123456` (код заменяется кодом сессии).

Каждый push изменений `public/` в `main` запускает workflow **Deploy GitHub Pages**. Он проверяет код и публикует только каталог `public/`. Исходники Edge Function и SQL в Pages не попадают. В Settings → Pages источником должен быть **GitHub Actions**.

Конфигурация браузера находится в `public/cloud-config.js`: URL API и publishable key публичны по назначению. Service-role ключ не хранится в GitHub и доступен только серверной функции через окружение Supabase. При подключении другого домена нужно обновить `siteUrl`, условие `enabled` и разрешённый Origin в Edge Function.

Облачная авторизация сохраняет привычный вход email + пароль. Это собственные аккаунты ProSlide в PostgreSQL, а не аккаунты панели Supabase и не Supabase Auth: пароль хэшируется PBKDF2-SHA256 (600 000 итераций, индивидуальная соль), сервер хранит только SHA-256 случайных токенов сессий. Токены браузера хранятся в localStorage, поэтому доступны JavaScript этого сайта; не добавляйте сторонние скрипты. Срок сессии автора — 30 дней. Подтверждение email и восстановление пароля пока отсутствуют.

Таблицы закрыты для `anon` и `authenticated`, RLS включён без разрешающих политик: доступ идёт исключительно через Edge Function с проверкой владельца или токена участника. Информационное уведомление [RLS enabled, no policy](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) ожидаемо для этой модели. Функция `proslide_vote` атомарно проверяет текущий слайд, паузу и завершение перед записью; RPC доступны только `service_role`.

Исходная схема: `supabase/schema.sql`. Обновления API выполняются отдельно от Pages — деплоем `supabase/functions/proslide-api/` в проект Supabase. `verify_jwt=false` в конфигурации нужен потому, что API проверяет собственные авторские и гостевые токены; это не отключает авторизацию приложения.

## Возможности

- Регистрация и вход авторов; личная библиотека презентаций.
- Редактор: заголовок, описание, добавление, удаление, дублирование и перестановка слайдов, три цветовые темы, предпросмотр, явное сохранение.
- Шесть типов слайдов: информационный, один ответ, несколько ответов, облако слов, открытый ответ, оценка от 1 до 5.
- QR-код генерируется локально, без обращения к стороннему сервису. Участникам не нужны аккаунт и приложение.
- Общая сессия для разных устройств, синхронизация текущего вопроса и результатов каждые 1,5 секунды.
- Экран ведущего: переключение слайдов, пауза ответов, скрытие результатов от аудитории, полноэкранный режим, завершение.
- Гистограммы, средняя оценка, текстовые ответы и облако слов с частотами. Слова нормализуются по регистру; повтор одного слова в ответе не увеличивает его вес.
- История сессий и CSV для Excel, включая все слайды с ответами. Результаты сохраняются после завершения и перезапуска сервера.
- Один ответ на слайд от участника в текущем браузере. Повторные параллельные запросы защищены уникальным ключом БД.

## Быстрый запуск

Нужен **Node.js 24+**. Установка npm-зависимостей и сборка не требуются.

```sh
git clone https://github.com/shevyakovys/proslide.git
cd proslide
node server.js
```

Откройте **http://localhost:3000**, нажмите «Создать аккаунт», зарегистрируйтесь и выберите «Попробовать готовый пример» или «Создать презентацию».

1. Настройте слайды в редакторе и сохраните.
2. Нажмите «Начать показ». Каждый запуск создаёт отдельную сессию и код.
3. Покажите аудитории QR-код. Участники могут также открыть `/join` и ввести код.
4. Переключайте слайды кнопками. Участник может ответить только на текущий слайд.
5. Завершите сессию и скачайте CSV из истории.

Пароли авторов — от 10 символов. Предустановленных аккаунтов нет.

### Телефоны в одной Wi-Fi сети

Сервер слушает `0.0.0.0:3000`. Откройте приложение **на компьютере ведущего по его LAN-адресу**, например `http://192.168.1.10:3000`, а не по `localhost`. QR-код автоматически будет содержать этот адрес. Подключите телефоны к той же сети. В брандмауэре должен быть разрешён входящий TCP-порт 3000 для этой сети. Изолированные гостевые Wi-Fi сети могут блокировать соединение устройств.

### Доступ через интернет

Для онлайн-версии выше сервер уже заменён Supabase. Если нужна **независимая установка с SQLite**, используйте Node-сервер и постоянный диск на VPS или контейнерном хостинге. Этот локальный режим не использует Supabase.

```sh
docker compose up -d --build
```

Docker хранит базу в volume `proslide-data`. Укажите публичный HTTPS-адрес в `.env` рядом с `compose.yaml`:

```dotenv
PUBLIC_URL=https://slides.example.com
```

Настройте DNS и HTTPS reverse proxy на порт 3000. Например, Caddy:

```caddyfile
slides.example.com {
    reverse_proxy localhost:3000
}
```

`PUBLIC_URL` должен точно совпадать с адресом, по которому пользователи открывают приложение. HTTPS в этой переменной включает Secure cookies. Не задавайте HTTPS URL при тестировании через обычный HTTP. Рекомендуется одна точка входа и один экземпляр приложения с локальным постоянным диском.

При запуске без Docker переменные можно передать через окружение или файл:

```sh
node --env-file=.env server.js
```

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `PORT` | `3000` | HTTP-порт |
| `PUBLIC_URL` | пусто | Адрес QR-кода и допустимый Origin запросов; без завершающего `/` |
| `DB_PATH` | `data/proslide.sqlite` | Путь к SQLite |

Для резервного копирования остановите приложение и сохраните каталог `data` / Docker volume, затем запустите снова. Не копируйте только основной SQLite-файл во время записи: используется WAL.

## Архитектура

- `server.js` — HTTP API и статические файлы; стандартные модули Node.js, `node:sqlite` и `node:crypto`.
- `public/app.js` — браузерный интерфейс без сборки и внешних CDN.
- `public/styles.css` — адаптивные стили редактора, ведущего и участника.
- `public/vendor/qrcode.js` — библиотека [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator), MIT; лицензия рядом с файлом.
- `test/app.test.js` — интеграционные тесты на встроенном `node:test`.
- `public/cloud-api.js` — адаптер облачного API; на GitHub Pages вместо локальных HTTP cookies используются токены в заголовках.
- `supabase/functions/proslide-api/` — облачное API, проверка данных и агрегация результатов.
- `supabase/schema.sql` — PostgreSQL-таблицы, индексы, ограничения доступа и атомарная запись ответов.
- `test/cloud.test.js` — отдельный интеграционный тест развёрнутого Supabase API; по умолчанию пропускается, чтобы CI не создавал аккаунты на работающем сайте.

В локальном режиме аккаунты, авторизация, презентации, снимки сессий, участники и ответы хранятся в SQLite; онлайн — в PostgreSQL. При запуске сессия получает снимок презентации: последующие изменения редактора не меняют уже идущее выступление. Удаление презентации не удаляет историю.

В локальном режиме пароли хэшируются `scrypt` с индивидуальной солью, сессии передаются HttpOnly/SameSite cookies. Облачная авторизация описана выше. Оба API проверяют владельца и Origin, валидируют данные и ограничивают частоту входа/отправки. SQL параметризован; пользовательский текст экранируется при выводе; CSV защищён от интерпретации формул. При скрытых результатах API участника не возвращает их.

## Проверки

```sh
node --check server.js
node --check public/app.js
node --test
```

GitHub Actions запускает проверки на Node 24 при push и pull request. Тесты покрывают разные устройства, все типы ответов, нормализацию облака, ограничения доступа, скрытые результаты, паузу, завершение, повторные одновременные ответы, экспорт, а также перезапуск с сохранённой БД.

Облачный API дополнительно проверен на реальном проекте Supabase: регистрация и вход, изоляция авторов, два участника, все типы ответов, параллельные повторы, скрытие результатов, экспорт, завершение и запрет прямого чтения таблиц/RPC с публичным ключом. Для повторного запуска задайте `PROSLIDE_CLOUD_TEST=1` и выполните `node --test test/cloud.test.js`. Тест создаёт отдельные аккаунты с адресами `@example.invalid`; их точные адреса сохраняются в игнорируемый `test-results/cloud-test-users.json` для последующей очистки. Не запускайте его против другого проекта без адаптации конфигурации.

Вручную в браузере проверены создание аккаунта и презентации, повторное сохранение после правок, показ QR-кода, вход участника, отправка слов, обновление облака и переключение вопроса; мобильный интерфейс проверен на ширине 390 px.

## Границы первой версии

Это рабочая базовая версия, а не полная копия всех функций Юнислайда. Пока нет импорта PPTX/PDF, AI-генерации, викторин с баллами, совместного редактирования, сброса пароля по email и модерации свободных ответов. Облако показывает до 100 наиболее частых слов; экспорт содержит все. Авторизация участника анонимна и привязана к cookie: другой браузер или очистка cookies позволит войти как новый участник. Это инструмент вовлечения аудитории, не система подтверждённого голосования.

Нагрузочный тест на массовое мероприятие не проводился. При большом числе участников стоит перейти от периодического опроса API к push-обновлениям и добавить серверные агрегаты. Для регистрации авторов в открытом интернете следует отдельно настроить антибот-защиту и восстановление аккаунтов. Результаты свободных ответов сразу отображаются, если ведущий их не скрыл.
